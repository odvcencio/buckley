# Preserve raw one-use output and derive a locked patch candidate

Return only a directly applicable unified Git diff. Do not wrap it in Markdown fences and do not include prose before or after the diff.

## Current defect

The command currently treats the raw assistant content as both durable evidence and the directly applicable patch. After the one permitted provider request, it writes `--output` and then rejects three response shapes repeatedly observed in real bounded runs:

1. A single whole-response fence:

   ````text
   ```diff
   diff --git a/file b/file
   ...
   ```
   ````

2. A valid unified diff whose final byte is not `\n`.
3. A complete unified diff with stale hunk counts that `git apply --check --recount` can safely recount against the exact clean worktree.

This wastes useful work even though normalization can be deterministic and content-preserving. It also checks output-path collisions only after the provider call, wasting the one-use request when a raw output already exists.

The current strict test deliberately expects all three shapes to fail:

```go
func TestValidatePatchResponse(t *testing.T) {
    tests := []struct {
        name    string
        content string
        wantErr bool
    }{
        {name: "applicable diff", content: applicableDiff},
        {name: "fenced prose prefix", content: "```diff\n" + applicableDiff + "```\n", wantErr: true},
        {name: "missing final newline", content: strings.TrimSuffix(applicableDiff, "\n"), wantErr: true},
        {
            name:    "truncated hunk",
            content: strings.Replace(applicableDiff, "+return an applicable unified diff\n", "", 1),
            wantErr: true,
        },
        {
            name:    "wrong hunk counts",
            content: strings.Replace(applicableDiff, "@@ -1 +1 @@", "@@ -1,2 +1,2 @@", 1),
            wantErr: true,
        },
        {
            name:    "nonexistent context",
            content: strings.Replace(applicableDiff, "-return a unified diff\n", "-absent line\n", 1),
            wantErr: true,
        },

    // Each case invokes validatePatchResponse against a fresh exact fixture
    // and asserts that validation never changes the worktree.

```

The baseline focused suite is green only because these useful responses are expected failures:

```text

ok m31labs.dev/buckley/cmd/buckley-ox-once
```

## Required command contract

Add a required `--candidate` argument alongside the required `--output` argument.

- `--output` remains the exclusive raw-evidence file. Its bytes must be exactly the assistant content returned by `oxAlphaPatchText`: no trimming, newline insertion, fence removal, recounting, or other normalization.
- `--candidate` is a separate exclusive mode-0600 file containing only the deterministic normalized candidate.
- Both paths must be explicit, distinct, and absent before provider dispatch. Detect existing regular files, directories, and symlinks before `config.Load`, client construction, or `CompletePatch`. Keep the final writes `O_CREATE|O_EXCL` so a race still fails closed.
- Preflight must not truncate, overwrite, follow, or remove an existing path. If either path collides, return before spending the one-use request.
- Do not create a candidate unless raw preservation succeeded, normalization succeeded, and candidate validation succeeded.
- If normalization or validation fails, preserve the raw file exactly, leave the candidate absent, and return an error that names the raw path and explains candidate rejection.
- If both succeed, print both exact paths. Never modify either file after its successful exclusive close.

The paths may be outside the repository, as in existing use. Do not relax or re-run the exact-worktree gate around them.

## Bounded deterministic normalization

Derive the candidate from raw bytes with only these transformations:

1. Accept a bare response only when byte zero begins `diff --git `.
2. Alternatively accept exactly one whole-response fence whose first line is exactly `````diff\n```, whose last fence line is exactly ````` ```, and which has no bytes or prose before the opening fence or after the closing fence except one optional final newline. Strip only those two fence lines.
3. Reject other fence labels, unclosed fences, nested or multiple fences, backticks inside a bare response, leading/trailing prose, whitespace prefixes, empty fence bodies, or a body that does not begin `diff --git `.
4. Append exactly one final `\n` to the candidate only when its last byte is not `\n`. Do not otherwise rewrite bytes, paths, context, hunk headers, or line endings.
5. Reject NUL bytes and syntactically incomplete/truncated diff structures. Never invent a missing file header, hunk line, context line, or closing fence. Use a detectable truncation fixture such as an unclosed whole-response fence or an incomplete `diff --git`/`---`/`+++`/hunk sequence; do not claim that a syntactically complete deletion can be distinguished from an intended deletion.
6. Validate the normalized bytes against the exact clean repository with exactly the equivalent of:

   ```text
   git -C <root> apply --check --recount --whitespace=nowarn -
   ```

`--recount` may ignore stale numeric hunk counts, but it must not relax path lookup or source context. Nonexistent context and malformed/truncated candidates remain errors. Validation must not change the index or worktree.

The candidate may retain stale count text; its applicability contract is the explicit `--recount` validation above. Do not implement a hunk-count rewriter.

## Required tests

Add focused, table-driven tests that prove:

1. A bare applicable diff produces byte-identical raw output and an identical candidate.
2. A single exact whole-response `diff` fence remains byte-identical in raw output and yields only the inner diff as candidate.
3. A missing final newline remains missing in raw output and appears exactly once in the candidate.
4. Stale hunk counts remain byte-identical in raw output and pass candidate validation only through `--recount` against the fixture repository.
5. Leading prose, trailing prose, an unsupported fence label, multiple/nested fences, an unclosed fence, an empty body, NUL content, malformed headers, nonexistent source context, and a syntactically incomplete/truncated diff are rejected with no candidate file.
6. Raw and candidate SHA-256 values differ exactly when normalization changes bytes, and repeated derivation of the same raw bytes is deterministic.
7. Existing raw or candidate paths—including symlinks—are rejected by preflight without changing their bytes or targets. Identical/aliased path spellings fail closed.
8. An integration-style synthetic Git repository proves the candidate is accepted by `git apply --check --recount`, validation leaves the worktree clean, and then a separate test apply produces the intended tracked-file change.
9. Exclusive output permissions remain `0600`; failed writes clean up only the file created by that invocation and never remove a replacement or pre-existing path.

It is acceptable to split normalization, validation, and exclusive-path preflight into small package-local helpers. Keep interfaces concrete and single-use; do not introduce a new package or abstraction layer.

## Exact current orchestration

The current request/output order is:

```go
func run() error {
    var repoRoot, exactHead, promptPath, outputPath string
    flag.StringVar(&repoRoot, "repo", "", "canonical clean Git worktree root")
    flag.StringVar(&exactHead, "head", "", "exact full HEAD commit OID")
    flag.StringVar(&promptPath, "prompt", "", "repo-relative prompt blob committed at --head")
    flag.StringVar(&outputPath, "output", "", "exclusive output file")
    flag.Parse()

    if repoRoot == "" || exactHead == "" || promptPath == "" || outputPath == "" {
        return errors.New("--repo, --head, --prompt, and --output are required")
    }
    canonicalRoot, err := canonicalDirectory(repoRoot)
    if err != nil {
        return err
    }
    if err := requireExactCleanHead(canonicalRoot, exactHead); err != nil {
        return err
    }
    ctx, cancel := context.WithTimeout(context.Background(), 12*time.Minute)
    defer cancel()
    rule, prompt, err := formTrackedOSSPrompt(ctx, canonicalRoot, exactHead, promptPath)
    if err != nil {
        return err
    }
    cfg, err := config.Load()
    if err != nil {
        return fmt.Errorf("load Buckley config: %w", err)
    }
    provider := cfg.Providers.OpenRouter
    client, err := model.NewOneUseOSSOpenRouterClient(provider.APIKey, provider.BaseURL, model.OxAlphaOpenRouterModelID, rule, prompt)
    if err != nil {
        return err
    }
    defer client.Close()

    response, err := client.CompletePatch(ctx)
    if err != nil {
        return fmt.Errorf("Ox Alpha request failed: %w", err)
    }
    content, err := oxAlphaPatchText(response)
    if err != nil {
        return err
    }
    if err := writeExclusiveOutput(outputPath, []byte(content)); err != nil {
        return err
    }
    if err := validatePatchResponse(ctx, canonicalRoot, []byte(content)); err != nil {
        return fmt.Errorf("raw Ox Alpha response preserved at %s: %w", outputPath, err)
    }
    fmt.Printf("saved one Ox Alpha response for %s at %s\n", exactHead, outputPath)
    return nil
}
```

The current validator is:

```go
func validatePatchResponse(ctx context.Context, root string, content []byte) error {
    if !bytes.HasPrefix(content, []byte("diff --git ")) {
        return errors.New(`content does not begin with "diff --git "`)
    }
    if !bytes.HasSuffix(content, []byte("\n")) {
        return errors.New("content does not end with a newline")
    }

    cmd := exec.CommandContext(ctx, "git", "-C", root, "apply", "--check", "--whitespace=nowarn", "-")
    cmd.Stdin = bytes.NewReader(content)
    cmd.Env = append(os.Environ(), "GIT_CONFIG_NOSYSTEM=1", "GIT_TERMINAL_PROMPT=0")
    var stderr bytes.Buffer
    cmd.Stderr = &stderr
    if err := cmd.Run(); err != nil {
        detail := strings.TrimSpace(stderr.String())
        const maxDetailBytes = 512
        if len(detail) > maxDetailBytes {
            detail = detail[:maxDetailBytes]
        }
        if detail == "" {
            detail = err.Error()
        }
        return fmt.Errorf("git apply --check rejected response: %s", detail)
    }
    return nil
}
```

The existing exclusive writer already uses `O_CREATE|O_EXCL`, mode `0600`, and identity-checked cleanup. Preserve those guarantees.

## Acceptance

The patch must be minimal, gofmt-clean, and limited to the command and tests. Raw evidence must remain byte-for-byte authoritative; normalization must be finite and deterministic; validation must use `--recount` without weakening source-context checks; collisions must be rejected before provider dispatch; and the candidate must be a separate exclusive artifact. Do not reconstruct or “helpfully” edit patch semantics. All existing tests plus the new focused and synthetic-repository tests must pass under normal and race execution.
