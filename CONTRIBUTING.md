## Contributing to Buckley

Thanks for investing time to improve Buckley! Please read this guide before opening issues or PRs.

### Ground Rules
- Follow the local conventions in `AGENTS.md`; it is the source of truth for workflow and coding norms.
- Keep the tree clean: do not revert user changes, and prefer small, reviewable PRs.
- Add concise comments only when behavior is non-obvious.
- Run formatters (`gofmt`/`go fmt`) on Go changes and equivalent tooling for other languages.

### Development Workflow
1. Clone the repo and install Go 1.26.0+; `go.mod` is the authority for the current floor.
2. Export a model provider key (e.g., `OPENROUTER_API_KEY`) for end-to-end runs.
3. Make your changes in a feature branch; include tests where behavior changes.
4. Run the fast suite before opening a PR:
   ```bash
   ./scripts/test.sh
   ```
   Use `GO_TEST_TARGET=all ./scripts/test.sh` or `go test ./...` for broader coverage when needed.
5. Open a PR with a clear description and screenshots/log snippets for UI or UX-affecting changes.

### Offline Readiness Regression Checklist

Use this checklist when preparing a release or changing agent result, model capability, durability, snapshot, or UI/headless execution behavior. Keep it offline unless the change explicitly requires a live provider. CLI details live in [`docs/CLI.md`](docs/CLI.md); operational symptoms belong in [`docs/troubleshooting.md`](docs/troubleshooting.md).

#### Current model-independent reliability posture

Buckley's offline readiness posture is evidence-backed but intentionally
bounded. It now requires safe degradation when model capability or pricing
metadata is unknown, stale, invalid, or unauthoritative: unknown metadata must
not grant optional capabilities, satisfy positive cost caps, or be reported as
known-free spend. Recovery paths preserve public drafts, usage, tool/command
evidence, and bounded model identity for diagnosis while keeping private
reasoning and raw provider text out of public result surfaces; incomplete
results remain incomplete and must not be accepted, posted, approved, or
ranked as finished work. Durable/restart/cancel coverage protects retained
command/effect evidence from uncertain replay and documents the exact SQLite
operator limit: deadline-bearing steady-state `sessionexec` command/effect
mutations shorten SQLite busy waits to the caller deadline. After durable
acceptance, cancellation cleanup uses fresh bounded contexts (currently 5
seconds each) for `EndEffect`, `Complete`, and fallback `Release`; it is not
bounded by the original request deadline and can run sequentially past it while
preserving no-replay/effect fencing. Observation endpoints may materialize
expiry/ambiguity state and use caller-bounded retry slices. Startup/WAL/
migration/manual/experiment-store paths remain outside that caller-deadline SLA
(see
[`docs/troubleshooting.md`](docs/troubleshooting.md#a-sqlite-operation-is-slow-or-did-not-stop-exactly-at-my-cancellation-deadline)).

Coordinator-worker, oneshot, ACP/LSP, chatcheck, experiments, and UI/headless
paths carry explicit result, identity, and rich usage/cost-evidence regressions,
but only for the anchored surfaces and offline fixtures listed below. Retained
experiment snapshots support offline comparison of stored experiment/run/eval
rows across releases; they are not full transcripts, atomic historical database
snapshots, execution attestations, or future API certifications (see
[`docs/CLI.md`](docs/CLI.md#experiment-snapshots)). The maintained process is
frozen-source normal/race evidence with exact commands, hashes, logs, and
scoped diff checks, not a claim that every future provider, CI environment,
live account policy, or user-facing integration has been exhaustively certified.
The historical `rlm` configuration namespace is retained.
`rlm.coordinator.stream_partials` controls coordinator progress publication to
iteration hooks and `rlm.iteration` telemetry; it is not a text-token streaming
control, and it does not alter terminal result or diagnostic behavior (see
[`docs/CONFIGURATION.md`](docs/CONFIGURATION.md#coordinated-execution-legacy-mode-key-rlm)).

- Outcome rules: incomplete public drafts, usage, tool/command evidence, and bounded model identity should be preserved for diagnosis, but incomplete results must not be treated as accepted work, approvals, posts, or rank-eligible completions. Unknown/changing provider metadata must not grant optional capabilities. Deadline-bearing steady-state `sessionexec` command/effect mutations shorten SQLite busy waits to the caller deadline. After durable acceptance, `EndEffect`, `Complete`, and fallback `Release` cleanup use fresh bounded contexts (currently 5 seconds each), not the original request deadline; sequential cleanup can outlast that deadline while preserving no-replay/effect fencing. Observation endpoints may materialize expiry/ambiguity state and use caller-bounded retry slices. Startup/WAL/migration/manual/experiment-store paths have no caller-deadline SLA and may wait for their configured busy/retry policy.

### Issue & PR Guidance
- Bugs: include reproduction steps, expected/actual behavior, environment (OS, Go version), and logs if available.
- Features: describe the problem first, then the proposed solution and alternatives considered.
- Security issues: **do not** open a public issue; follow `SECURITY.md`.

### High-Priority Areas
- Test coverage needs the most help in: `pkg/model`, `pkg/tool`, `pkg/ui`, `pkg/session`, and `pkg/cost`.
- Please prefer small, focused PRs that add tests around existing behavior before refactors.

### Code of Conduct
Be respectful and collaborative. Assume good intent and keep discussions focused on the work. See `CODE_OF_CONDUCT.md`.
